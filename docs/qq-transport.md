# QQ 连接状态与超时诊断

NapCat 模板心跳间隔为 30000ms；实测心跳可晚于 30 秒。单次接收超时不能证明 QQ 账号掉线或 NapCat 卡死。

鱼脑空闲 30 秒后发送只读 `get_status`，再等待 10 秒。收到有效 JSON 对象即证明连接仍有数据流，恢复正常空闲等待；若仍无有效数据则关闭旧连接，5 秒后重连。探测不是消息发送重试，也不是必须由特定响应解除的账号健康检查。探测次数仅表示出现空闲，不能当作故障次数。

`connected` 表示 OneBot WebSocket 已建立；`self_id` 表示会话身份；`account_online` 表示平台最近明确报告的账号状态（未知时为 null）。心跳或成功探测返回的 `online=false` 优先于历史会话身份，`/qq/status.online` 随即为 false。账号重新在线时可通过后续心跳恢复，无需重建 WebSocket。

接收线程优先处理 API 响应与账号状态，生命周期事件落库、聊天及 LLM 调用交给工作线程。`/qq/status.transport` 提供接收/工作线程存活、队列长度、最近收帧/收消息时间、处理起点与空闲探测次数。时间戳为 Unix 秒；计数和时间随鱼脑进程重启重置。`login_reason` 来自历史 QQ 日志，仅离线时作为诊断线索，在线时返回 unknown。

发送回复最多等待确认 30 秒，必须收到 `retcode=0` 才记作成功；超时或断连未收到确认时，通过 `SendUnconfirmedError` 报告结果未知，聊天和自主说话均记 warning/action“可能已送达，未获确认”，避免自动重试导致重复消息。明确的平台拒绝仍记为失败。分段发送中断时，前面的消息可能已经发送。`/qq/api.ok` 也只有在收到成功响应时为 true，调用者仍应检查 response 中的平台结果。平台 API 确认成功不等于对方已读。

修改鱼脑源码后同步 `app/assets/fish/`；新增模块时还需更新部署向导 `wizard.dart` 的资源映射，更改 app 内嵌部署资源时同步提升 app 版本。30 秒空闲阈值与模板心跳相同是允许的，不能退回“超时立即重连”的判断。

验证：`python -m unittest discover -s fish/tests -v`。真机验证需覆盖超过 30 秒的空闲周期，确认探测计数增长时没有新增重连记录；另发私聊确认完整收发链路。

戳一戳通知：NapCat 私聊以 sender_id 为实际发起者、target_id 为目标，user_id 仅表示会话对象；群聊以 user_id 为发起者。自身身份优先取事件 self_id，回退当前会话身份；缺失参与者只记“未知用户”，不推断为被戳。group_id 缺失或为 0 表示私聊。自主戳一戳的 API 确认日志与实际事件日志分开：无响应为结果未知，retcode 非零为拒绝，只有 retcode=0 才记请求获确认；不自动重试。
