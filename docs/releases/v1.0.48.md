# v1.0.48：记忆召回与来源核对修复

版本 1.0.48+62，2026-10-31。GitHub 发布提供 `app-release.apk` 及 `app-release.apk.sha256`，覆盖安装保留应用数据；已安装的 Termux 鱼脑仍须配套更新。

## 行为变化

- 当前问题与最近用户话题分别检索，助手旧回复不再参与混合查询；按当前说话人、会话及隐私范围提供候选。
- 新增 MemoryService，通过已经配置的模型做语义选择，支持没有共同字词的问法；不需要新增数据库服务、embedding key 或本地模型。
- 用户事实、助手经历和无原始来源的旧记录明确分开。回答提供有效原始来源及自然时间，相邻用户消息只作为语境补充。
- 同会话连续追问能继承已使用的证据 ID；每轮及发送前重查来源、版本和删除状态。缓存只保留 ID，不复制已忘正文。
- 短期聊天保留独立的时间/会话元数据，避免跨日混淆及元数据被照抄进回复。心跳和行动使用同一来源展开与范围校验。
- 人工纠正有持久的来源标记；派生旧记录无法仅凭一个来源 ID 就被当成原始用户陈述。
- 后台提炼使用带原话片段及言语性质的新契约。普通即时问题、测试开场、回声及片段不应形成长期待办；新事实/约定的原话片段须能在所引事件里找到。分类与提炼仍依赖模型，不能据此保证语义永不误判。

## 数据与升级

新增运行模块 memory_service.py，其余配套模块为 autonomy.py、brain.py、life.py、memory.py、memory_policy.py、memory_system.py、qq_bot.py。共 18 个运行模块已同步到安装资源和向导清单。

无新增数据库表或批量旧记忆迁移。原始聊天、旧记忆、配置和令牌保留；旧低质量事项没有自动批量删除。新人工纠正使用已有 event_key 字段标注来源。

先覆盖安装 APK，再配套更新鱼脑并重启。专用工具 deploy_memory_recall_update.py 校验前后源码哈希、备份源码和 SQLite、检查离线数据库未被改写，再检查服务与 QQ 进程身份；失败回退源码。备份仅留设备本地。

## 成本与边界

有候选记忆时，回复会增加一次现有模型的语义检索请求及相应 token 用量。检索网络操作超时为 15 秒，失败退回本地检索并标记 unavailable；该设置不是整轮请求的严格墙钟总时限。

候选目录和证据包有明确预算。超过预算标记 incomplete，不能把未扫到解释为用户从未说过。当前未部署向量索引、大规模语义目录或完整 v3 事实投影；长期规模与成本仍需观察。

部署预检时 QQ 已离线且有结果未确认的登录任务，鱼脑正常。本次不重放登录操作，保留原 QQ 主进程与启动器；不能将记忆升级视为 QQ 登录恢复。
