# v1.0.46：QQ 登录与生命周期调度修复

版本：`1.0.46+60`。已构建并配套更新连接的手机。GitHub 发布入口：[v1.0.46](https://github.com/99cz99/fishbrain/releases/tag/v1.0.46)，附 APK 和 SHA-256 校验文件。

原流程将 WebUI 请求失败、原生登录初始化、OneBot 掉线混在一起，可能在原生登录尚未结束时重复登录或重启；停止命令还会匹配容器启动器。现在由独立的 `QQController` 统一管理启动、停止、快捷登录、换码及配置应用，HTTP 只返回排队结果，状态接口提供后续任务结果。

- 停止可抢占其他任务；副作用执行前校验任务代次、目标账号、平台启用和用户停止意图。重复在途请求复用任务；更换账号取消旧任务。
- 按真实可执行文件、PID、启动时间及专属会话组识别 QQ。先等待原生主进程退出，再清理启动器；停止无法确认时禁止叠加启动。Android 外部 UID 的 hidepid 拒绝不当作 QQ 自身不可读。
- 明确区分控制鉴权、网络不可达、请求结果未知、原生拒绝和已接受登录。只有明确鉴权拒绝允许重新鉴权一次；已提交的登录或配置写入超时不重放。原生账号状态未知时也不以历史候选列表授权再次登录。
- 初始化、扫码已接受及重连期间保留会话。账号原生 ready 与当前代次 OneBot 连通分别判定；业务传输故障不触发重新登录。
- OneBot 配置保留已有设置，通过 WebUI 配置接口保存和热加载；换码使用原生 RefreshQRcode。移除运行中的 Windows GUID 自动写入路径。
- 控制器独立于 LLM 心跳线程。明确停止意图和任务结果持久化；鱼脑服务重启后查询未知结果，恢复未完成停止，保留原生拒绝结果。自动拉起有宽限、冷却、熔断和稳定在线后清零。
- App 展示排队/处理中/结果未知/账号已登录/OneBot 已连接的区别，禁用重复操作，透出业务拒绝原因；不再用旧账号配置文件或账号已配置来宣称登录成功、自愈正在执行。

联动：`server.py`、`qq_control.py`、`qq_bot.py`、App API/模型/登录页/部署页、全部 17 个嵌入模块、向导映射、通用部署模块白名单、异步 OneBot 更新工具及诊断工具。升级要求 App 和 Termux 源码成套更新；单装 APK 不会替换已经运行的 Python 文件。

## 部署与回退

本机使用 `tools/deploy_qq_control_update.py`，要求阶段目录包含三份耦合模块、通用部署工具及匹配的 `qq-control-manifest.json`。清单以规范化换行后的 SHA-256 约束设备旧版和待装新版，避免覆盖未审查修改。每次成套替换前生成设备本地源码和数据库备份；失败成套回退源码，不自动回放原生登录或还原在线账号资料。

源码/数据库备份：`.backups/qq-control-update-20261030-152025/`（本轮改动前）、`.backups/qq-control-update-20261030-153209/`（最终状态未知保护前）。回退应选匹配版本的 App 和整套源码；恢复旧数据库或原生资料需要先停止对应写入者并审查后续数据，不能将旧快照直接覆盖在线数据。

完整原生快照工具为 `tools/qq_control_cold_device.py`：`prepare` 在停止确认后校验快照；`start --backup <目录>` 先消耗单次门禁再发启动，HTTP 响应丢失也不自动重发；`observe` 只查询。`tools/verify_qq_control_device.py --exercise` 要求账号已在线，只验证已登录短路及配置应用，不发送聊天。

原 `recover_qq_scan_device.py` 已联动改为请求控制器换码，不再绕过统一调度直接停止鱼脑、杀进程、复制不完整的 Login/Registry20 或另启 proot；`refresh_qq_login_device.py` 也返回异步任务信息。历史局部备份不视为已验证的完整凭据快照。
