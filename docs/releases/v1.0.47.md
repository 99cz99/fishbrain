# v1.0.47：修复慢 WebUI 导致的登录状态误判

版本 `1.0.47+61`。在用户再次报告 App 无法登录后，真机确认 QQ 已经登录：OneBot `get_status` 返回 online/good=true，`get_login_info` 的身份与当前连接一致；放宽等待的 WebUI 查询同样返回 isLogin/coreReady=true、phase=ready。一次包含鉴权的只读查询耗时 8.243 秒，旧后端却使用 2 秒等待，将控制接口的慢响应当作账号证据缺失，导致 App 长期显示未知。

- WebUI 只读及鉴权请求允许更长等待，单次控制调用按总预算限制；原生写操作仍保留短超时，结果未知不重放。配置读取移出副作用锁，最终写入前重新校验任务代次，保证停止抢占后不会执行迟到写入。
- OneBot 明确在线回报单独记录时间与账号，断连/停止时清除。WebUI 不可用时，只允许同一 QQ 进程会话内、身份匹配且 90 秒内的明确在线回报确认账号；任意新帧不能延长旧账号证据。明确离线、其他会话/账号、过期证据或原生身份冲突都不能判业务在线。
- `/qq/status` 新增 `account_source` 和 `native_ready`，区分 WebUI 原生证据与 OneBot 当前在线证据。`control_error` 保留真实控制接口异常，账号在线不要求 WebUI 始终快速响应。
- App 当前在线证据优先于历史登录错误/未知结果；正在执行的停止仍优先显示。同步后端、17 个嵌入运行模块和部署工具，新增只读状态来源对照工具。

验证：186 项 Python、24 项 Flutter 测试及静态分析通过。新增回归覆盖慢查询/短写入预算、账号证据时效及会话/身份绑定、明确离线优先、停止抢占后的迟到配置写入，以及旧操作错误不能遮住当前在线状态。

真机配套更新时仅重启鱼脑，原 QQ 主进程与启动器身份保持不变；配置、令牌及更新前离线验证的数据库内容保留。更新后鱼脑、OneBot、WebUI 均确认同一账号在线，未提交登录或二维码刷新，未重启 QQ，未发送测试消息。后续安装及界面核验记录见 `../qq-login-slow-control-verification-2026-10-30.json`。

此修复针对“已登录但控制查询慢导致 App 误判”。没有将它描述为修复所有原生登录失败；手机重启、系统强制回收和长期稳定性仍需分别验证。用户升级须同步 APK 与 Termux 鱼脑源码，已配套更新设备无需重复部署。
