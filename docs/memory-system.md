# 记忆系统 v2

目标是保持长期相处的连续性，同时让每条认识可追溯、可更新、可删除。当前实现使用 SQLite 与现有 LLM，不新增向量服务或图数据库。

## 数据与迁移

`memory_system.py` 是 `Store` 的记忆存储 mixin。复用 memories 表，增加 entity_id、source_ids、status、occurred_at、processed、due_at、last_attempt、pinned、event_key。

- episode：对方原始话语形成的事件证据，不含助手回复、抓取网页或视觉模型补充。
- fact：明确陈述的事实。replaces 只能更新同人物、同范围、同类型的旧事实，旧记录保留为 superseded。
- belief：暂定认识，至少引用两条事实/自身经历；不能跨人物或跨隐私范围。原事实不被整批吸收。
- intention：明确的约定或待反馈事项。支持完成、取消、已尝试联系；日期不确定时 due_at=0，不主动触发。
- experience：实际主动发送的结果，区分 confirmed、unconfirmed、failed_or_partial，不把确认发送解释为已阅读。

首次升级旧数据库，先通过 SQLite backup 保存 `<数据库文件>.pre-memory-v2.db`。旧 `subject=self, kind=fact` 洞察因来源不明隔离为 quarantined，不召回；发现这类洞察时清除可能受污染的派生 self_profile，保留用户 persona。原始记录保留。备份含私人数据，不提交到仓库。回滚需停止服务并恢复升级前备份；不要混用新数据与旧代码。

旧 private 范围的 QQ 主体可从 scope 恢复稳定账号 ID；其他旧昵称记录不猜测绑定到哪个账号。新记录使用 `qq:<账号>`，重名和改名不改变身份。跨平台不自动关联。

## 写入与召回

QQ 在生成回复前持久化事件，优先保留有效的平台发生时间；凭据先脱敏。忽略明确 @ 别人的消息；其余可能回复的消息进入事件队列。事件键阻止平台重放造成重复记忆。后台单线程每 30 秒检查，从真正最早的可重试事件定位人物和范围，最多 10 条一批。失败按批次退避，其他人物仍可继续处理；队列与重试状态持久化。`/status.memory_queue` 提供积压数与最老等待时间；后台调用仍消耗模型额度。

LLM 只提出结构化候选。数据库验证依据仍有效、人物和范围一致，统一事务写入并标记处理完成；删除与纠正发生在模型调用期间时，结果作废。

召回先按隐私、当前版本、人物和所需类型过滤，再通过 SQLite 字符倒排索引选最多 256 个候选并重排，允许空结果；以近期对话补充查询。最多 8 条、合计 4000 字符（不是精确 token 预算）。稳定人物匹配加分，有效事实优于暂定认识和原始事件。当前事件及直接派生内容从召回和工作摘要中排除。事实替换保留来源，但用 memory_history 标记旧原话和关联回复，退出当前知识；内部历史检索可显式 include_history=True。索引无需 SQLite 可选 FTS 扩展或向量服务，不宣称已解决所有同义表达。

工作摘要是实时重建的近期事件摘录和未完事项，不是 LLM 生成的长期会话摘要。删除会清理索引，没有旧摘要缓存复活。事实类活跃额度目标 300；新记忆保护 24 小时，固定记录不淘汰，因此可能暂时超过额度。淘汰采用归档，保留证据。处理完的普通事件超过最近 500 条且满 24 小时后归档；自身经历超过最近 300 条且满 24 小时后归档。短期消息每会话保留最近 200 条。归档和日志仍占磁盘，暂不自动永久清除历史。

## 隐私与人格

owner 全渠道；group 仅本群和 global；private 仅本人和 global；未知范围不返回结果。**主人在群里发言仍按 group 处理**。反思必须继承证据范围，不能自动升成 global。

人格统一，经历按范围保密。`personality.py` 管理独立的 `personality_traits` 表：自动条目保存维度、内容、依据 ID 和状态；`settings.self_profile` 保存手动条目，读取设置时合并为所有聊天共用的画像。公开提示词只注入条目文本，不注入依据、私人故事或关系记忆。

QQ 实际回复发送完成后，将原始对方话语及实际回复记录为同范围的 self/experience，并引用原 episode；未确认或失败的回复不记为已完成交流。主动发送仍记录其真实结果。自身经历增加反思积分。经验引用原事件允许跨人物，但必须同范围；普通事实与 belief 的人物和范围约束不变。

人格提炼直接使用最多 40 条有有效依据的自身 experience/belief，不再要求 global。模型先提候选，再通过单独一次隐私和证据审查调用确认；只接受明确布尔通过的条目，并校验短文本、标识符、已知人物名称和依据。至少两个独立根事件支持才能形成新特质；修正已有特质须至少三个独立根事件的反证。不能把对方偏好、单次情绪、关系事实或助手自称当自身稳定特质。每次最多两条，保留四维容量限制；没有依据时保持原人格。

`growth_status` 保存最近尝试、成功时间和 running/updated/unchanged/insufficient_evidence/error/interrupted 状态；自动检查间隔一小时，仍受 allow_self_evolve 控制，手动自省可强制尝试。服务重启将未完成状态标记 interrupted。模型隐私审查不是形式化的信息流保证，仍需真实模型长期验证。

删除或纠正依据只调整关联的自动条目；仍有至少两项独立支持时保留，否则撤销。无关记忆变更不清空人格，手动条目保留。画像编辑保存保留未修改自动条目的来源；HTTP 保存必须携带读取时的 self_profile_revision，过期返回 409。生成后重新验证依据及画像/人设版本，防止删除、重置或人工编辑后旧结果复活。旧隔离洞察不自动恢复，用户 persona 不受迁移影响。

## 主动跟进

心跳及行动提示可看到主人 owner 范围的到期事项，仍由模型决定是否联系。近 15 分钟有主人互动则暂不提示。超过 7 天的事项不继续自动追问。跟进 send_message 必须携带 intention_id；执行前再次校验人物、范围、时间、状态并原子领取。领取后即使发送未确认、失败或进程退出，也不自动重试。midnight_ok=false 时 00:00–08:00 不执行主动文本发送。

这是针对带 intention_id 的跟进保护，不是对所有自由生成聊天进行语义去重。明确日期允许过去 7 天至未来 366 天，轻微逾期不会改成日期未知。陪伴和到期跟进采用 owner 范围，并只向模型提供给主人联系的工具；其他混合或公开行动使用 global 范围背景。返回工具名也要在实际提供的工具集合内。没有新建多代理服务。

## 2026-10-29 审查修复约束

- `memory_policy.py` 统一信任规则、身份代号、资料封装和秘密凭据过滤。聊天 system 不再拼接记忆正文、外部昵称、头像和引述；这些内容以明确的不可信 user 资料块提供。所有成长与行动入口也声明证据不能变成指令。这不能形式化保证真实模型永不误判。
- 聊天、心跳、行动共用底层 persona、人工画像和自动画像渲染规则。行动阶段按目标范围重新验证第一阶段的依据 ID，删除后不使用旧快照。公开行动不继承 owner 原始背景；私有跟进不同时提供公开发布工具。
- 事实和事项先筛类型再限量，并补充同人物同范围的相关旧事实检索；反思按合格类型、人物和范围选取并轮转检查。无合格组不扣积分，有处理时只消费对应数量的积分；新积分保留。
- 人工移除自动特质写入 personality_vetoes，生成和写入都检查；人工编辑有内容的维度不接受新的自动条目，以免冲突。用户在编辑器明确重新添加原文可解除对应否决。请求驱动回复会标注来源性质，提炼规则要求行为和反馈印证，避免把重复自述算成独立人格证据。
- HTTP 人工保存行为字段会记录 user_locked_settings；自动进化重新读取锁和原值，避免覆盖并发编辑。静默时段、审批和启用平台始终由用户控制，自动进化目前只可能调整未锁定的聊天尺度。
- 事件、自身经历、短期上下文及诊断日志的新内容在写入时脱敏；fact/belief/intention 中检测到秘密凭据则拒绝或跳过。首次升级策略 v3 前对已有文件库做 SQLite backup，生成 `<数据库>.pre-memory-policy-v3.db`，随后对旧记忆、短期上下文、日志脱敏，并隔离含凭据的长期认识、撤销失效画像。备份仍含原内容，只保留在本机，不入库；恢复须停止服务后使用完整备份。
- 审批后的空间发布、小黑盒帖子和评论在实际执行结束时记录 confirmed/unconfirmed/failed_or_partial 自身经历，以审批 ID 去重结果；请求审批和启动线程均不算执行成功。其他自主变更工具也记录明确结果，读工具不把返回内容自动当事实。
- `python tools/sync_fish_assets.py` 自动同步所有运行模块并生成部署向导文件清单；发布前运行 `python tools/sync_fish_assets.py --check`，并从安装资源目录独立验证状态与心跳。
- `fish/tests/fixtures/memory_semantics.json` 提供否定、引用、日期、同名、隐私、凭据、注入、人格反馈及同义查询的匿名评测案例。该文件是语义验收集，不代表已运行真实模型评测。`python tools/benchmark_memory.py` 使用临时合成数据测量检索，不打开真实数据库。

## 管理与删除

GET /memories 支持 limit（最多 1000）和 offset，监管页面可加载更多，显示隔离和历史状态。
PUT /memories/<id> 支持 content 纠正、pinned 固定，以及 intention 的 done/cancelled；DELETE 忘记。

忘记沿来源追溯到原始事件，再清理它派生的事实和认识，清空对应内容并留下去重墓碑；清理相关短期上下文，并撤销失去足够依据的派生人格条目。一次事件中的其他事实可能一同移除，App 会说明并确认。纠正采用同一清理规则，再写入用户提供的新事实；不开放一键将隔离记录发布到 global。

诊断日志和升级前备份不会随单条记忆删除；它们不参与记忆提炼。心跳只使用 status 类诊断日志，避免从聊天日志找回已忘内容。已发往外部的消息不能撤销；正在生成的回答不是事务的一部分。

回归覆盖迁移幂等、跨人物/范围、群聊主人隐私、更新与反思失效、事务回滚、删除及重放、后台整理、未确认不重复发送、近期互动和取消、App 来源展示与管理。
